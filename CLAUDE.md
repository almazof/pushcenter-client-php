# PushCenter client-php — правила репозитория

## Контракт шлюза — источник истины

- Формат запросов/ответов и правила валидации задаёт HTTP API v1 шлюза, а не эта
  библиотека. Клиент не может «договориться» о новом поле или послаблении —
  сначала меняется API шлюза, потом реализация здесь.
- Тесты сериализации гоняются на golden fixtures из `tests/fixtures/`
  (происхождение и порядок обновления — `tests/fixtures/README.md`).
- Клиентская валидация — пре-флайт-подмножество серверных схем. Ослаблять
  серверные правила клиентом запрещено, ужесточать сверх них — тоже: и то и
  другое приводит к расхождению поведения между клиентом и шлюзом.

## Архитектура и стиль

- PHP 8.1+ (осознанно шире шлюза — клиент ставится в разные проекты),
  `declare(strict_types=1)` в каждом файле, PSR-4 `PushCenter\Client\` → `src/`.
- **Zero-dependency ядро**: в `require` только `psr/*`-интерфейсы. Конкретные
  HTTP-библиотеки не добавляются; встроенный транспорт — только ext-curl
  (`CurlTransport`), PSR-18 — через `Psr18Transport`.
- Все DTO immutable (`readonly`-свойства), валидируются в конструкторе;
  невалидный запрос не доходит до сети.
- Побочные эффекты за интерфейсами: `TransportInterface` (сеть),
  `SleeperInterface` (время), `LoggerInterface` (PSR-3). Тесты используют фейки
  из `tests/Support/`, сетевые вызовы в юнит-тестах запрещены.

## Инварианты (не ломать)

- Ретрай ТОЛЬКО с тем же `idempotency_key`: ключ фиксируется до цикла ретраев.
  Новый ключ при ретрае — нарушение контракта и потенциальный дубль пуша.
- `4xx` (кроме 429) не ретраится; `429` не ретраится по умолчанию
  (`RateLimitedException` + `retryAfterSeconds`); `429 limit_exceeded` — никогда.
- Замер payload — тем же алгоритмом, что у шлюза:
  `strlen(json_encode($p, JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES))`,
  лимит 3500 байт.
- Формула `IdempotencyKey::deterministic()` (рекурсивный `ksort` + sha256 по
  pipe-склейке) зафиксирована тестом и задокументирована в README: её меняют
  только осознанно и ломающе — это сломает дедупликацию у живых отправителей.
- `fireAndForget` покрывает только `notify*`; register/bind/unbind всегда бросают.

## Качество (обязательно перед коммитом)

- `scripts/check.sh` — единая команда: PHPStan level max (0 ошибок) + юнит-тесты.
  Дефолтный прогон самодостаточен: ни docker, ни внешних сервисов.
- `scripts/check.sh --integration` — тесты против живого шлюза; требуют его
  локальной копии и его Postgres/Redis, в состав репозитория шлюз не входит.
- Коммиты — conventional commits, на английском.
